# UX and accessibility review — 2026-11-13

The first recorded visual, usability and accessibility pass over the web app. It closes the
evidence gap behind the UX score in `docs/quality-scorecard.md` (category 10).

## Setup

- Stack: `web/scripts/local-stack.ps1` (Anvil, PostgreSQL, API, indexer, seeded launches, trades,
  graduations, forum posts and artwork), web on the `next dev` server at `127.0.0.1:3417`.
- Browser: Chrome through Chrome DevTools MCP, in an isolated context with no wallet, so every
  flow was seen as a signed-out visitor. Signing flows stay covered by the Anvil e2e gates.
- Viewports: 1440×900 and 1920 desktop, 929 (small laptop or tablet), 375×812 mobile (touch).
- Pages: home, explore (Trending, New), token detail (curve token), create, wallet, forum,
  analytics, leaderboard.
- Automated: Lighthouse 13 (accessibility, best practices, SEO, agentic browsing). Performance
  was not scored, because the dev server is not representative.

## Open items (not fixed here)

These are product or design decisions, or larger pieces of work. Each is ranked by how much it
weighs on a first-time user.

1. ~~**Token image is a URL field only.**~~ **Closed on `task/launch-image-upload`.** The launch
   form takes an image file and a description. Both are saved after the launch receipt, through
   the existing verified creator endpoints at revision 0. See
   `docs/specs/2026-11-13-launch-image-upload-preflight.md`.
2. ~~**Tiny prices are unreadable.**~~ **Closed on `task/tiny-price-notation`.** Four or more
   leading fraction zeros now show as a subscript count (0.0₈1699). This applies to the header,
   recent trades, the opening price, the wallet's average cost and the chart axis. Screen readers
   get the full decimal.
3. ~~**Default slippage is 5 %**~~ **Closed on `task/default-slippage`** (product owner chose 2 %).
   Every trade form now starts at 2 %, and the presets are 1, 2, 5 and 10 %, so 10 % stays one tap
   away on fast curves.
4. ~~**The trade panel scrolls inside itself**~~ **Closed on `task/ux-open-items`:** a card taller
   than the viewport now scrolls with the page and sticks by its bottom edge. Original finding: at 900 px viewport height once a quote is shown. The
   sign action then sits below an inner scroll.
5. ~~**"Edit token metadata" and the claim rows show to every visitor**~~ **Closed on
   `task/ux-open-items`:** the editor renders only for the connected creator wallet (the API still
   authorizes writes), and a claim line shows only with a positive balance or a claim under way.
   Original finding: ("Server authorization
   required", "Claimable creator fees: Unavailable"). Hide them unless the connected wallet is the
   creator.
6. ~~**Sparse chart.**~~ **Closed on `task/ux-open-items`:** fewer than five points get markers,
   pinned edges and a "few trades so far" note; the volume series no longer draws a label on the
   price axis. Original finding: A token with a few trades draws one point in the middle of an empty area.
   The volume label overlaps the price axis.
7. ~~**Token detail hero is about 600 px tall on desktop.**~~ **Closed on `task/ux-open-items`:**
   at 1024 px and wider the header is one row (142 px, from 350 px); at 1440×900 the trade card
   starts at y = 328 (from 608). Original finding: At 1440×900 the trade panel starts at
   the fold.
8. ~~**API `404` for missing token metadata**~~ **Closed on `task/ux-open-items`:** the page no
   longer asks for metadata or image revisions unless the creator's wallet is connected, so visitors
   get a clean console. Original finding: is logged as a console error on every token page. An
   empty `200` (or the page not asking) would keep the console clean.
9. **"Updating" never clears on an idle local chain.** This is a dev-environment artefact (Anvil
   mines only on transactions, so blocks never reach the finality depth). It does not affect a
   live chain, so it is noted only.
